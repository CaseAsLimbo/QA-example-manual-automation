## Проверка безопасности формы логина на странице логина <br>[TC-Stack_Overflow-SECURITY-LOGIN-001](https://github.com/CaseAsLimbo/QA-example-manual-automation/blob/efcb3fb64ad9c19da12787208de7ce756c347212/manual/test-cases/TC-Stack_Overflow-SECURITY-LOGIN-001.md) (XSS и SQL инъекции)
>[!IMPORTANT]
> build: 1.5.6.7\
> Дата проверки: 16.06.2026\
> Окружение: Linux Ubuntu 22.04, Firefox\
> Проверяющий: Намазов Максим

| №   | Проверка                                                                                                           | Результат                                                                                                                                        |
| --- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Валидация поля "Почта" на клиентской стороне (HTML5 type="email")                                                  | Браузер не даёт отправить форму при явно некорректном формате, показывает всплывающую подсказку                                                  |
| 2   | Валидация поля "Пароль" на минимальную длину (если задано, например, 8 символов)                                   | При вводе пароля короче минимума – сообщение "Пароль должен содержать не менее 8 символов" (после серверной проверки)                            |
| 3   | Валидация полей на серверной стороне (отправка запроса с некорректным email в обход клиента)                       | Сервер возвращает ошибку "Неверный формат почты", код 400, без раскрытия дополнительной информации                                               |
| 4   | Проверка на SQL‑инъекцию в поле "Почта" (например, `' OR '1'='1`)                                                  | Ошибка аутентификации, данные экранируются, запрос не ломает логику приложения                                                                   |
| 5   | Проверка на XSS в полях ввода (например, `<script>alert(1)</script>`)                                              | Введённый скрипт не выполняется, отображается как текст в поле или в сообщении об ошибке, без интерпретации                                      |
| 6   | Передача учётных данных по HTTPS                                                                                   | Все ресурсы на странице загружены по HTTPS, форма отправляется на защищённый endpoint (https), в DevTools вкладка Security не показывает проблем |
| 7   | Наличие CSRF‑токена в форме                                                                                        | В теле запроса присутствует скрытое поле `authenticity_token` или заголовок X-CSRF, токен обновляется при каждом обновлении страницы             |
| 8   | Обработка повторного использования истёкшего CSRF‑токена                                                           | Сервер отвечает 403/422, вход не выполняется                                                                                                     |
| 9   | Проверка на отсутствие передачи пароля в URL (GET‑запрос)                                                          | Форма отправляется методом POST, пароль не виден в строке адреса                                                                                 |
| 10  | Блокировка аккаунта после N неудачных попыток входа                                                                | После 5-10 неверных попыток появляется капча или временная блокировка (проверить сообщение о превышении лимита)                                  |
| 11  | Установка сессионных cookie после успешного входа                                                                  | Cookie `acct` или `user` имеет флаги `Secure`, `HttpOnly`, `SameSite=Lax` (или Strict). Отсутствует в `document.cookie`, если HttpOnly           |
| 12  | Выход с устройства (логаут) – косвенная проверка, что сессия инвалидируется                                        | После логаута повторный заход на страницу входа не авторизует автоматически (нет активной сессии)                                                |
| 13  | Отображение пароля при переключении – не сохраняется ли открытое состояние после отправки (кэширование на клиенте) | После отправки формы и неудачной попытки поле пароля снова скрыто (точки), даже если ранее был включён просмотр                                  |
| 14  | Проверка автозаполнения: атрибут autocomplete для поля пароля                                                      | Поле "Пароль" имеет `autocomplete="current-password"`, поле "Почта" – `autocomplete="username"`, менеджеры паролей корректно распознают поля     |
| 15  | Обработка спецсимволов в пароле (кавычки, слеши, эмодзи)                                                           | Спецсимволы корректно передаются и проверяются, вход успешен, если пароль верен                                                                  |
| 16  | Проверка на отсутствие утечки информации о существовании аккаунта (user enumeration)                               | При неверном email и при неверном пароле выдаётся идентичное обобщённое сообщение, время ответа сервера не отличается значительно                |
