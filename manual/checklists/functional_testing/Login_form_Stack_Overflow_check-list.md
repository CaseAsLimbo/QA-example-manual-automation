## Проверка функциональности формы логина
>[!IMPORTANT]
> build: 1.5.6.7\
> Дата проверки: 15.06.2026\
> Окружение: Linux Ubuntu 22.04, Firefox\
> Проверяющий: Намазов Максим
## Позитивные проверки:	
### Общие
1. Вход с корректной парой e‑mail и пароль существующего аккаунта
	- **Результат:** Успешный вход в аккаунт
 	- [TC-LOGIN-001](https://github.com/CaseAsLimbo/QA-example-manual-automation/blob/4a31e4b7908492223109846fcc9ccdab529c3974/manual/test-cases/TC-LOGIN-001.md) 
2. Переход по ссылке "Забыли пароль?"	
	- **Результат:** Открывается страница восстановления пароля (проверить корректность URL)
3. Переход по ссылке "Зарегистрируйтесь"	
	- **Результат:** Открывается страница регистрации (/users/signup)
4. Клик по логотипу Stack Overflow (в верхней левой части формы)	
	- **Результат:** Переход на главную страницу https://ru.stackoverflow.com
5. Переключатель видимости пароля: клик по "глазику" (иконка)	
	- **Результат:** Пароль отображается открытым текстом, иконка меняется на "перечёркнутый глазик". Повторный клик – скрывает символы (возврат к точкам/звёздочкам)
6. Автодополнение браузера (менеджер паролей)	
	- **Результат:** Поля заполняются сохранёнными данными, форма работает штатно
7. Вход сразу после восстановления пароля (проверка, что новый пароль работает)	
	- **Результат:** Успешный вход с новым паролем
### OAuth
8. Вход через кнопку "Войти через GitHub" (при наличии привязанного аккаунта)	
	- **Результат:** Перенаправление на GitHub OAuth, после согласия возврат на сайт, успешная авторизация
 	- [TC-LOGIN-002](https://github.com/CaseAsLimbo/QA-example-manual-automation/blob/4a31e4b7908492223109846fcc9ccdab529c3974/manual/test-cases/TC-LOGIN-002.md)
9. Вход через кнопку "Войти через Google"	
	- **Результат:** Редирект на Google OAuth, успешный вход
10. Вход через кнопку "Войти через Яндекс"	
	- **Результат:** Редирект на https://passport.yandex.ru/, успешная OAuth-авторизация
11. Вход через кнопку "Войти через Вконтакте"	
	- **Результат:** Редирект на https://id.vk.ru/, успешная авторизация через VK
12. Вход через кнопку "Войти через Facebook"	
	- **Результат:** Редирект на https://www.facebook.com/v2.0/dialog/oauth, успешная авторизация через Facebook
## Негативные	проверки:
### Общие
1. Повторная отправка формы (двойной клик по кнопке "Войти")	
	- **Результат:** Повторный запрос не отправляется, кнопка блокируется на время обработки (атрибут disabled) либо запрос идемпотентен
2. Вход после истечения сессии на другом устройстве	
	- **Результат:** Старая сессия инвалидируется, вход успешен с созданием новой сессии
3. Вход с отключёнными cookies в браузере	
	- **Результат:** Сообщение о необходимости включить cookies для авторизации (или перенаправление на страницу с предупреждением)
 	- [TC-LOGIN-003](https://github.com/CaseAsLimbo/QA-example-manual-automation/blob/4a31e4b7908492223109846fcc9ccdab529c3974/manual/test-cases/TC-LOGIN-003.md)
4. Длительное бездействие на странице (истечение CSRF‑токена)
	- **Результат:** После отправки формы с истёкшим токеном – сообщение об ошибке "Время сеанса истекло, обновите страницу"
### Поле "Почта"
5. Отправка формы с незаполненным полем "Почта"	
	- **Результат:** Форма не отправляется, подсветка поля с ошибкой "Почта не может быть пустой"
 	- [TC-LOGIN-004](https://github.com/CaseAsLimbo/QA-example-manual-automation/blob/4a31e4b7908492223109846fcc9ccdab529c3974/manual/test-cases/TC-LOGIN-004.md)
6. Отправка формы с незаполненным полем "Пароль"	
	- **Результат:** Поле подсвечено, сообщение "Пароль не может быть пустым"
7. Отправка с пустыми обоими полями	
	- **Результат:** Подсвечены оба поля, соответствующие ошибки валидации
8. Ввод почты без символа @ (класс невалидных)	
	- **Результат:** Сообщение "Указанный адрес не является действительным адресом электронной почты."
9. Ввод почты без доменной части (например, user@)	
	- **Результат:** Сообщение "Указанный адрес не является действительным адресом электронной почты."
10. Ввод почты с пробелами внутри (например, user @example.com)	
	- **Результат:**  Сообщение "Указанный адрес не является действительным адресом электронной почты."
11. Вход с почтой с символами + в имени пользователя(до символа @) для существующего аккаунта
	- **Результат:** Сообщение "No user found with matching email", вход заблокирован
12. Граничное значение длины почты: ровно 254 символа (макс. допустимая длина e‑mail по RFC)	
	- **Результат:** Поле принимает, валидация не ругается. Если используется БД с ограничением, проверить сохранение. При превышении (255+) – ошибка "Слишком длинный адрес"
13. Ввод почты, содержащей кириллические символы (например, пользователь@пример.рф)	
	- **Результат:** Сообщение "Указанный адрес не является действительным адресом электронной почты."
14. Вход с неверным паролем для существующей почты	
	- **Результат:** Сообщение об ошибке "Неверный адрес почты или пароль" (без уточнения, чтобы не палить наличие аккаунта)
15. Вход с несуществующей в системе почтой	
	- **Результат:** Обобщённое сообщение "Неверный адрес почты или пароль"
### Поле "Пароль"
16. Переключатель видимости при пустом поле пароля	
	- **Результат:** Иконка может быть скрыта или неактивна, или клик не приводит к ошибке – ожидаемое поведение: иконка отображается, но при пустом поле переключение бессмысленно (визуально не ломается)
17. Копирование/вставка пароля из буфера обмена (в т.ч. спецсимволы)	
	- **Результат:** Пароль корректно вставляется, спецсимволы (!@#$%^&\*()) не искажаются
 	- [TC-LOGIN-005](https://github.com/CaseAsLimbo/QA-example-manual-automation/blob/4a31e4b7908492223109846fcc9ccdab529c3974/manual/test-cases/TC-LOGIN-005.md)
